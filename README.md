# 🌾 AgriTrack AI

**Localized AI farm advisor for Nigerian smallholder farmers.**

Built for the **IdentArk × 3MTT AI Hackathon 2026 — "Build AI. Solve Local."**

AgriTrack AI is a mobile-first web app where a Nigerian farmer describes their situation in plain
language (crop, state, season, problem) and receives **localized, AI-generated, actionable advice**
grounded in their state's agro-ecological zone, their crop, and **live weather data**.

---

## What it actually does (honest claims)

- **AI farm advisor (chat):** Ask a question about planting, pests, weather, or soil care. The answer
  is generated by a real LLM (OpenAI or Google Gemini) using a system prompt that forces
  Nigerian-localized, crop-specific, actionable advice. If no AI key is configured, it falls back to
  a clearly-labeled rule-based answer from local reference data — it never pretends to be AI when it
  isn't.
- **Localized context:** A static dataset of Nigerian states, agro-ecological zones, and common crops
  (maize, rice, cassava, yam, sorghum, millet, cowpea) with typical planting windows is injected into
  the AI prompt so answers are genuinely local.
- **Live weather:** Uses **Open-Meteo** (free, no API key) geocoded to the farmer's state to fetch
  current conditions + a 7-day forecast, which is fed into the AI prompt.
- **Farm log + dashboard:** Farmers record their farm name, crop, state, and planting date. The
  dashboard lists their farms and can generate an AI "next action" suggestion for each.

### What it does NOT do (be honest in your demo)
- ❌ It does **not** diagnose crop diseases from images.
- ❌ It does **not** predict or report real market prices.
- ❌ It is **not** a substitute for a certified agronomist or plant pathologist.
- ❌ It does **not** have user accounts / multi-user roles (single shared farm log for the MVP).

## Tech stack

- **Frontend:** React 18 + Vite (mobile-first, minimal JS, works on low-end phones)
- **Backend:** Node.js + Express
- **AI:** OpenAI (`gpt-4o-mini`) or Google Gemini (`gemini-1.5-flash`) — real API calls
- **Weather:** Open-Meteo (no API key)
- **Database:** Supabase (optional) with an in-memory fallback so it runs with zero setup

## Getting started

### 1. Prerequisites
- Node.js 18+ and npm

### 2. Install dependencies
```bash
npm run install:all
```

### 3. Configure environment
```bash
cp .env.example .env
```
Then edit `.env` and add **at least one** AI key (the app works without it, but the AI experience
needs it):
- `OPENAI_API_KEY=sk-...` **or** `GEMINI_API_KEY=...`

Optional — for persistent farm data, add your Supabase credentials:
- `SUPABASE_URL=...`
- `SUPABASE_ANON_KEY=...`
- Run `supabase/schema.sql` in your Supabase SQL editor.

If Supabase is not configured, the farm log runs in-memory (data resets on restart).

### 4. Run in development
```bash
npm run dev
```
- Frontend: http://localhost:5173
- Backend API: http://localhost:4000

### 5. Build & run in production
```bash
npm run build
npm start
```
The server serves the built frontend from `client/dist` at http://localhost:4000.

## API endpoints

| Method | Endpoint          | Description                                  |
|--------|-------------------|----------------------------------------------|
| GET    | `/api/health`     | Health check + active AI provider            |
| GET    | `/api/states`     | Localized data (zones, crops, states)        |
| GET    | `/api/weather?state=X` | Current + 7-day weather for a state     |
| POST   | `/api/advice`     | Generate AI advice `{user, state, crop}`     |
| GET    | `/api/farms`      | List farms                                   |
| POST   | `/api/farms`      | Add a farm `{farmName, crop, state, plantingDate}` |
| DELETE | `/api/farms/:id`  | Delete a farm                                |

## Security notes
- **No real API keys are committed.** All secrets live in `.env` (git-ignored). See `.env.example`.
- The Supabase anon key is used for the MVP demo; for production, add proper auth and row-level
  security policies.
